# **แผนแม่บทโครงการ (Project Master Plan — ฉบับปรับปรุงสมบูรณ์)**

**โครงการ:** Senic Billing Next (Multi-Tenant SaaS Billing & Inventory Platform)  
**อัปเดตล่าสุด:** 13 พฤศจิกายน 2026

---

## **1. วัตถุประสงค์โครงการ**

1. พัฒนาระบบออกเอกสารการเงินและภาษีครบวงจร 5 โมดูลหลัก (**ใบเสนอราคา, ใบกำกับภาษี, ใบเสร็จรับเงิน, บิลเงินสด, ใบส่งของ** รวมถึงใบลดหนี้/ใบเพิ่มหนี้) บนสถาปัตยกรรม Cloud Multi-Tenant
2. รองรับระบบคลังสินค้า (Inventory Stock Deduction & Restock) และการสแกนบาร์โค้ด (Barcode POS-ready)
3. รองรับมาตรฐานภาษีไทย (VAT 7% Inclusive/Exclusive, หัก ณ ที่จ่าย WHT, รายงานภาษีขาย Excel และ e-Tax Invoice XML มาตรฐาน ETDA)
4. แยกส่วนบริหารจัดการแพลตฟอร์ม (**Super Admin Portal — `admin-frontend`**) และส่วนผู้ใช้งานองค์กร (**SME Tenant Portal — `frontend`**) พร้อมระบบแพ็กเกจ (Subscription Plans & Quotas) และการชำระเงินออนไลน์ผ่าน **Omise**
5. ออกแบบ UX/UI ภายใต้คอนเซปต์ *"Professional, Futuristic, yet Warm"* รองรับ Dual Theme (`Warm Horizon` / `Deep Ocean`), 2 ภาษา (`ไทย` / `English`), และ Mobile-first PWA
6. ขับเคลื่อนการพัฒนาและควบคุมคุณภาพด้วยทีม **Multi AI Agents & Domain Specialists**

---

## **2. สถานะขอบเขตการทำงาน (Scope of Work & Milestones)**

* ✅ **Phase 1: Discovery, Architecture & Design System (เสร็จสมบูรณ์)**  
  * ออกแบบ Clean Architecture (.NET 10) และ Multi-Tenant Database Schema (PostgreSQL 16)  
  * ออกแบบ UI/UX Design System (Glassmorphism, Dual Themes `Warm Horizon` / `Deep Ocean`, Responsive Mobile BottomNav & FAB)  
  * วางโครงสร้างทีม Multi AI Agents (`.ai-agents/`, `.github/agents/`, `.github/skills/`)

* ✅ **Phase 2: Core Backend, Security & Document Engine (เสร็จสมบูรณ์)**  
  * พัฒนา API สำหรับเอกสารทั้ง 5 ประเภท + Credit/Debit Note และ 1-Click Document Conversion  
  * ระบบสร้างเลขที่เอกสารเรียงลำดับอัตโนมัติป้องกันการชนกัน (Optimistic Concurrency `DocumentNumberSequence`)  
  * ระบบ JWT Authentication, Granular RBAC (`Permission`, `RolePermission`), และ Audit Trail (`AuditInterceptor`)

* ✅ **Phase 3: Core Frontend, Real-time & Master Data (เสร็จสมบูรณ์)**  
  * พัฒนา SME Portal ด้วย React 19 + TypeScript + Vite + Tailwind CSS v4 + Zustand  
  * เชื่อมต่อระบบ Real-time Notification & Health Monitoring ผ่าน SignalR (`SenicBillingHub`, `SystemMonitorService`)  
  * พัฒนาหน้าจัดการลูกค้า (`CustomersPage`), สินค้า (`ProductsPage`), ตั้งค่าองค์กร (`SettingsPage`), และผู้ใช้งาน (`UsersManagementPage`)

* ✅ **Phase 4-6: Premium SaaS Foundations, AI & CI/CD Deployment (เสร็จสมบูรณ์ 100%)**  
  * เชื่อมต่อ Omise Payment Gateway (PromptPay QR, Payment Link, SaaS Subscription Checkout)  
  * ระบบออกบิลซ้ำอัตโนมัติ (`RecurringInvoiceWorker`), แจ้งเตือนบิลเกินกำหนด (`OverdueMonitorWorker`), และผู้ช่วย AI (`GeminiAIAssistantService`)  
  * ระบบสร้าง PDF (`QuestPdfService`), รายงานภาษีขาย Excel (`ClosedXML`), และ `ETaxXmlGenerator`  
  * ตั้งค่า Docker Multi-stage builds, `docker-compose.yml` และ GitHub Actions CI/CD สู่ Portainer

* ✅ **Phase 7-8: End-to-End Integration, SaaS Quota, Super Admin Portal & Automated QA (เสร็จสมบูรณ์ 100%)**  
  * แก้ไขและเชื่อมต่อการบันทึกสต็อก/บาร์โค้ด การตัดสต็อกและการคืนสต็อก (`Restock`) ครบทุกประเภทเอกสาร  
  * เชื่อมต่อปุ่มดาวน์โหลดรายงานภาษีขาย Excel, e-Tax XML, Server PDF, Public Shared Link และ `LineNotifyService`  
  * เปิดใช้งานระบบรักษาความปลอดภัย Super Admin Portal (`admin-frontend`), `SaBillingController`, และระบบบังคับใช้โควต้า (`MaxDocumentsPerMonth`, `MaxUsers`)  
  * ยกระดับรหัสผ่านเป็น Salted `PBKDF2-SHA256` (`PasswordHasher`) และสร้างชุดทดสอบอัตโนมัติ `SenicBilling.Tests` (`Passed 6/6`)

## **3. แผนการพัฒนาส่วนที่เหลือตามลำดับ (Sequential Remaining Roadmap: Phase 7 - 8)**

เพื่อให้ระบบมีความสมบูรณ์ 100% ในระดับ Production-Grade โดยไม่มีช่องโหว่หรือจุดที่เชื่อมต่อไม่ครบ จึงแบ่งแผนงานที่ค้างอยู่ออกเป็น 4 ลำดับ (Sprint) ดังนี้:

### **ลำดับที่ 1 (Phase 7.1): แก้ไข Bug วิกฤตและปรับ Contract ข้อมูลให้ตรงกัน (Critical Fixes & API Parity)**
* **ผู้เชี่ยวชาญหลัก:** `senic-inventory-pos-specialist`, `senic-etax-report-specialist`, `senic-ledger`, `senic-sage`, `senic-nova`
* **งานที่ต้องดำเนินการ:**
  1. **แก้ไขการบันทึกสต็อกและบาร์โค้ด (`ProductsPage.tsx`)**: แก้ `handleSave` ให้ส่งค่า `stockQuantity` และ `barcode` จริงตามที่ผู้ใช้กรอก (แทนการส่ง `stockQuantity: 0`) และแก้ `colSpan={7}` ในตารางสินค้า
  2. **เพิ่มการตัดสต็อกใน `TaxInvoiceController.cs` และระบบคืนสต็อก (Restock)**: ให้ใบกำกับภาษีตัดสต็อกสินค้าเหมือน `DocumentControllerBase` และเพิ่มลอจิกคืนสต็อกเมื่อ **ยกเลิกเอกสาร (Cancel)** หรือปรับปรุงจำนวนเมื่อ **แก้ไขเอกสาร (Update)**
  3. **ปรับจูน API Contract หน้า Dashboard (`DashboardController.cs` ↔ `DashboardPage.tsx`)**:
     * แก้ไข `/api/dashboard/tax-estimator` ให้มีค่าเริ่มต้น `year`/`month` เป็นเดือนปัจจุบัน และคืนค่าฟิลด์รวมภาษีหัก ณ ที่จ่าย (`whtDeducted`) ตรงกับ Frontend
     * แก้ไข `/api/dashboard/aging-report` และ `DashboardPage.tsx` ให้แสดงผลยอดหนี้ค้างชำระแต่ละช่วงอายุหนี้ (`current`, `1-30`, `31-60`, `61-90`, `>90 วัน`) ได้ตรงกัน
  4. **แก้ไขปุ่มแปลงเอกสารใน `DocumentPrintView.tsx` และปัญหาภาษาไทยเพี้ยน (Mojibake)**:
     * แก้ URL การแปลงเอกสารให้เรียก `POST /api/{controller}/{id}/convert` พร้อม Body `{ targetType: "TaxInvoice" }`
     * แก้ไขข้อความภาษาไทยที่เพี้ยนใน `DocumentControllerBase.cs`

### **ลำดับที่ 2 (Phase 7.2): เชื่อมต่อฟีเจอร์ระดับพรีเมียมให้ครบวงจร (End-to-End Premium Features Integration)**
* **ผู้เชี่ยวชาญหลัก:** `senic-etax-report-specialist`, `senic-ai-automation-specialist`, `senic-milo`, `senic-nova`
* **งานที่ต้องดำเนินการ:**
  1. **เชื่อมต่อปุ่มดาวน์โหลดในฝั่ง Frontend**:
     * เพิ่มปุ่มดาวน์โหลด **รายงานภาษีขายประจำเดือน (Excel `.xlsx`)** (`GET /api/reports/tax/export`) ในหน้า Dashboard และหน้ารายการใบกำกับภาษี
     * เพิ่มปุ่มดาวน์โหลด **e-Tax Invoice XML** (`GET /api/tax-invoices/{id}/e-tax-xml`) และ **Server PDF** (`GET /api/tax-invoices/{id}/pdf`)
  2. **ระบบ Public Shared Document Link (เปิดดูและชำระเงินโดยไม่ต้องล็อกอิน)**:
     * สร้าง Public Route (เช่น `/shared/:id` หรือรองรับโหมด Public ใน `/print/:id`) และ Public API Endpoint ที่ดึงข้อมูลเอกสารสำหรับลูกค้าปลายทาง พร้อมเรียก `MarkAsViewed` อัตโนมัติเมื่อลูกค้าเปิดลิงก์
  3. **ระบบส่งแจ้งเตือน LINE Notify อัตโนมัติฝั่ง Backend**:
     * สร้าง `ILineNotifyService` ส่งแจ้งเตือนเข้า LINE ขององค์กร (`Tenant.LineNotifyToken`) เมื่อลูกค้าชำระเงินสำเร็จผ่าน Webhook หรือเมื่อมีการเปิดอ่าน/ออกเอกสารสำคัญ
  4. **ตัวเลือกสินค้า (Product Picker) ในหน้าออกบิล (`InvoiceForm.tsx`)**:
     * เพิ่มปุ่ม/Autocomplete เลือกสินค้าจากฐานข้อมูลในแต่ละบรรทัดรายการ นอกเหนือจากการสแกนบาร์โค้ด

### **ลำดับที่ 3 (Phase 7.3): ยกระดับระบบ SaaS Multi-Tenant, Quota Enforcement และ Super Admin Portal**
* **ผู้เชี่ยวชาญหลัก:** `senic-saas-portal-specialist`, `senic-aegis`, `senic-atlas`, `senic-nova`
* **งานที่ต้องดำเนินการ:**
  1. **รักษาความปลอดภัย Super Admin APIs & Portal (`admin-frontend`)**:
     * เปิดใช้งาน `[Authorize(Roles = "SystemAdmin,SuperAdmin")]` ใน `SaTenantsController` และ `SaPlansController`
     * ติดตั้ง Dependencies ใน `admin-frontend`, เพิ่มระบบ Login/JWT Interceptor, เพิ่ม CORS origin ของ `admin-frontend` ใน `Program.cs`
  2. **พัฒนา `SaBillingController` และเชื่อมต่อข้อมูลจริงใน `admin-frontend`**:
     * สร้าง Endpoint สรุปสถิติแพลตฟอร์ม (จำนวน Tenants, Users, MRR, ประวัติ `BillingInvoice`) ให้หน้า `Dashboard.tsx` ของ Admin แสดงข้อมูลจริง
     * เพิ่ม Modal สร้างและแก้ไขแพ็กเกจ (`SubscriptionPlan`) ในหน้า `PackagesList.tsx`
  3. **ระบบตรวจสอบโควต้า (Quota Enforcement) และหน้าจัดการแพ็กเกจฝั่ง SME**:
     * เพิ่มการตรวจสอบ `MaxUsers` ตอนเพิ่มพนักงาน และ `MaxDocumentsPerMonth` (พร้อมอัปเดต `TenantUsageStat`) ตอนสร้างเอกสารใหม่
     * เพิ่มส่วนแสดงแพ็กเกจปัจจุบัน โควต้าคงเหลือ และปุ่มอัปเกรดแพ็กเกจในหน้า `SettingsPage.tsx`
     * รวมศูนย์หน้าจัดการพนักงาน (`/users` และ `/staff`) ให้เป็นมาตรฐานเดียวกัน

### **ลำดับที่ 4 (Phase 8): การเสริมความมั่นคงปลอดภัย การทดสอบอัตโนมัติ และความพร้อมก่อนขึ้น Production (Security, QA & Release Hardening)**
* **ผู้เชี่ยวชาญหลัก:** `senic-aegis`, `senic-argus`, `senic-hermes`, `senic-mnemosyne`
* **งานที่ต้องดำเนินการ:**
  1. **Security Hardening**:
     * อัปเกรดแพ็กเกจ NuGet เพื่อแก้ช่องโหว่ `System.Security.Cryptography.Pkcs` (NU1902 / NU1903)
     * ยกระดับการเข้ารหัสรหัสผ่านจาก Unsalted SHA-256 เป็น Salted Password Hashing (`PBKDF2` / `BCrypt`) พร้อมรองรับการ Migrate รหัสผ่านเดิมอัตโนมัติตอน Login
  2. **Automated Testing Suite (`SenicBilling.Tests`)**:
     * สร้างโปรเจกต์ xUnit ทดสอบสูตรคำนวณ VAT/WHT, การตัด-คืนสต็อก, การรันเลขเอกสารพร้อมกัน (Concurrency), และการกั้นข้อมูลข้าม Tenant (Tenant Isolation)
  3. **Production Release Verification**:
     * ตรวจสอบความพร้อมของ Docker Compose, Health Checks และอัปเดต Knowledge Base (`.ai-agents/knowledge/`)

## **4. ✅ แผนการพัฒนาต่อยอด Phase 9: ระบบใบสำคัญจ่าย/ภาษีซื้อ (Expense & Input VAT), หนังสือรับรอง 50 ทวิ และ LINE Messaging API (เสร็จสมบูรณ์ 100%)**

รายละเอียดฉบับเต็มอยู่ในเอกสาร [แผนการพัฒนา Phase 9 (Expense, Input VAT, WHT & LINE Messaging API).md](implementation_plan/%E0%B9%81%E0%B8%9C%E0%B8%99%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%9E%E0%B8%B1%E0%B8%92%E0%B8%99%E0%B8%B2%20Phase%209%20(Expense,%20Input%20VAT,%20WHT%20&%20LINE%20Messaging%20API).md) แบ่งออกเป็น 4 ลำดับ (Sprint 9.1 – 9.4) ดังนี้:

1. **Sprint 9.1 — ระบบบันทึกค่าใช้จ่าย / ใบสำคัญจ่าย และภาษีซื้อ (Expense Voucher & Input VAT Engine)**:
   * สร้างเอนทิตี `ExpenseRecord` (`EXP-YYYYMM-XXXX`) รองรับข้อมูลผู้ขาย (`VendorName`, `VendorTaxId`, `VendorBranch`), ภาษีซื้อ (`VatAmount`, `IsRefundableVat`), และภาษีหัก ณ ที่จ่าย (`WhtRate`, `WhtAmount`, `PndType`: `PND3`/`PND53`)
   * พัฒนา `ExpensesController` (`/api/expenses`) และเชื่อมต่อยอดภาษีซื้อเข้ากับ `DashboardController.GetTaxEstimator` เพื่อคำนวณภาษีมูลค่าเพิ่มสุทธิ (**ภ.พ.30 = ภาษีขาย - ภาษีซื้อ**)
2. **Sprint 9.2 — รายงานภาษีซื้อ (Input Tax Report), สรุป ภ.พ.30 และหนังสือรับรองหัก ณ ที่จ่าย (50 ทวิ PDF)**:
   * สร้าง API ส่งออก **รายงานภาษีซื้อ + สรุป ภ.พ.30 (Excel)** (`GET /api/reports/input-tax/export`) และ **รายงานหัก ณ ที่จ่าย ภ.ง.ด.3 / ภ.ง.ด.53 (Excel)** (`GET /api/reports/wht/export`)
   * พัฒนา `QuestPdfService` สำหรับพิมพ์ **หนังสือรับรองการหักภาษี ณ ที่จ่าย (มาตรา 50 ทวิ) PDF** (`GET /api/expenses/{id}/wht-certificate-pdf`)
3. **Sprint 9.3 — หน้าจอบริหารค่าใช้จ่าย ใบสำคัญจ่าย และ AI สแกนใบเสร็จอัตโนมัติ (`ExpensesPage.tsx` & AI Receipt Parser)**:
   * เพิ่ม `POST /api/ai-assistant/parse-expense` สกัดข้อมูลใบเสร็จ/ใบกำกับภาษีซื้อด้วย AI ช่วยกรอกฟอร์มอัตโนมัติ
   * พัฒนาหน้า `/expenses` และอัปเดตการ์ดประมาณการภาษีใน `DashboardPage.tsx` ให้แสดงทั้งภาษีขาย ภาษีซื้อ และภาษีสุทธิที่ต้องชำระ
4. **Sprint 9.4 — การเชื่อมต่อ LINE Messaging API & Webhook แบบสองทิศทาง และชุดทดสอบอัตโนมัติ**:
   * รองรับการตั้งค่า LINE Official Account (`LineChannelAccessToken`, `LineChannelSecret`, `LineDefaultTargetId`) ควบคู่กับ `LineNotifyToken`
   * สร้าง `LineWebhookController` (`POST /api/webhooks/line/{tenantId}`) พร้อมตรวจสอบลายเซ็น `X-Line-Signature` (`HMAC-SHA256`) เพื่อตอบกลับคำสั่งด่วน (`"สรุปยอด"`, `"ภาษี"`, หรือค้นหาเลขที่บิล) และเพิ่มชุดทดสอบ xUnit ใน `SenicBilling.Tests`

## **5. ✅ แผนการพัฒนาต่อยอด Phase 10: ระบบจัดซื้อและใบสั่งซื้อ (PO & Vendors), คลังสินค้าหลายสาขา (Multi-Warehouse) และเชื่อมต่อบัญชีอัตโนมัติ (เสร็จสมบูรณ์ 100%)**

รายละเอียดฉบับเต็มอยู่ในเอกสาร [แผนการพัฒนา Phase 10 (PO, Multi-Warehouse & Auto-Accounting).md](implementation_plan/%E0%B9%81%E0%B8%9C%E0%B8%99%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%9E%E0%B8%B1%E0%B8%92%E0%B8%99%E0%B8%B2%20Phase%2010%20(PO,%20Multi-Warehouse%20&%20Auto-Accounting).md) แบ่งออกเป็น 4 ลำดับ (Sprint 10.1 – 10.4) ดังนี้:

1. **Sprint 10.1 — ทะเบียนผู้ขาย (Vendor Master) & ระบบใบสั่งซื้อ (Purchase Order — PO)**:
   * สร้างเอนทิตี `Vendor`, `PurchaseOrder`, `PurchaseOrderLine` (`PO-YYYYMM-XXXX`), `VendorsController`, `PurchaseOrdersController` (`POST /receive` รับสินค้าเข้าคลังและสร้าง `ExpenseRecord` อัตโนมัติ) และ PDF ใบสั่งซื้อ
2. **Sprint 10.2 — คลังสินค้าหลายสาขา (Multi-Warehouse) และ Stock Movement Ledger**:
